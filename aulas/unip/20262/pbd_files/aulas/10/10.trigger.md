# Triggers



Triggers são comandos SQL salvos no banco de dados, ligados à uma tabela, que são ativados quando certos eventos ocorrem.

Então você pode criar um comando para acontecer sempre que houver uma ação de atualização de uma tabela, por exemplo.



Nesta aula vamos tratar de um problema e ver como as funções de *Stored Procedure* e *Trigger* podemos nos ajudar.

## Stored Procedure[^sp_w3][^sp_dev]
[^sp_w3]:[fonte w3schools](https://www.w3schools.com/mysql/mysql_stored_procedures.asp)
[^sp_dev]:[fonte dev mysql](https://dev.mysql.com/doc/refman/9.7/en/create-procedure.html)

Um *Stored Procedure* é um código pré-compilado e salvo que pode ser reusado.

Vamos considerar a seguinte tabela criada pelos [comandos](ddl_pizzas.txt)

##### Pizzas
| id_pizza|nome|preco|
|---|---|---|
|1|Marguerita|10|
|2|Frango|20|
|3|Frango com Requeijão|25|
|4|Mussarela|30|
|5|Calabresa|40|
|6|Lombo|40|

Vamos supor que precisamos fazer o comando de buscar uma pizza pelo nome.

Precisaremos escrever

```sql
SELECT * FROM Pizzas
WHERE nome LIKE '%frango%';
```

Para que não precisemos escrever o mesmo comando com frequência, podemos criar um *stored procedure*

##### sintaxe
```sql

DELIMITER //

CREATE PROCEDURE busca_pelo_nome(
    IN param1 datatype, 
    IN param2 datatype,
    OUT saida datatype
    )
BEGIN
  -- SQL_statements to be executed
  SELECT column1, column2
  FROM table_name
  WHERE columnN = paramN;
END //

DELIMITER ;
```

##### Explicação

O comando `CREATE PROCEDURE` cria um procedimento com o nome `procedure_name`, este procedimento pode ter argumentos de entrada e de saída.

A definição do procedimento está entre o comando `BEGIN` e `END`. Dentro do procedimento podemos escrever quaisquer comandos.

O uso do `DELIMITER` é para redefinir o que é o final de um comando para o sql. Neste caso mudamos o final do comando para `//` para não confundir com o `;` de dentro da definição do procedimento.

Vamos ver um exemplo:

```sql
DELIMITER //

CREATE PROCEDURE busca_pelo_nome(IN nome_buscado VARCHAR(20))
BEGIN
  SELECT * FROM Pizzas
  WHERE nome LIKE CONCAT('%', nome_buscado, '%');
END //

DELIMITER ;
```

Agora podemos chamar o procedimento com o comando `CALL`.

```sql
CALL busca_pelo_nome('frango');
```

### Saída

Um procedimento pode ter um valor de saída. Use o comando `OUT` nos argumentos para indicar que uma variável é a variável de saída.

Por exemplo, para calcular a média dos valores de todas as pizzas podemos fazer o seguinte procedimento.

```sql
DELIMITER //

CREATE PROCEDURE calcula_media_preco(OUT media FLOAT)
BEGIN
  SELECT AVG(preco) INTO media FROM Pizzas;
END //

DELIMITER ;
```

Para chamar o procedimento e guardar o valor da variável usamos a seguinte sintaxe:

###### sintaxe
```sql
CALL calcula_media_preco(@media);
SELECT @media;
```

###### Resultado
| @media|
|---|
|30.714284896850586|

**obs:** mas observe que a variável **não** existe fora da sessão em que ela foi criada. Isto quer dizer que tentarmos usar o valor de `@media` em um próximo comando, este valor será nulo.

#### Usando Procedure Em Outro Procedure

Como exemplo, vamos usar o procedimento de cálculo de média para aumentar, em uma porcentagem, todos os preços das pizzas que estão abaixo da média de preço:

```sql
DELIMITER //

CREATE PROCEDURE aumenta_abaixo_media(IN porcentagem DECIMAL)
BEGIN
  CALL calcula_media_preco(@media);

  UPDATE Pizzas
  SET preco = preco + (preco)*(porcentagem/100)
  WHERE preco < @media;
END //

DELIMITER ;
```

Chamando o procedimento com o valor 20 teremos um aumento de 20% das pizzas que estavam com o preço abaixo da média:

```sql
CALL aumenta_abaixo_media(20);
```
